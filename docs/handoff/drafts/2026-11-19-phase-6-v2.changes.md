# Phase 6 v2: what changed from the draft, and why

Date: 2026-11-19
Draft (v1): `.superpowers/drafts/2026-11-06-phase-6-catalog-divergence-design.md`, written against the code at Phase 3.
v2: `.superpowers/drafts/2026-11-19-phase-6-catalog-divergence-design.v2.md`, written against `build/v1` at 78db56f.
One line per change. "v1 section N" names the draft's section; "v2 N" the new spec's.

## Corrected against the code

- V1. v1 section 4 and Task 1 assumed the runner records reasoning. It does not: `runner/runner.py: _call_target` builds the target `Turn` without `reasoning_text` (`HANDOFF.md`, the Phase 4 Task 8 carry). v2 4.3 adds the copy, per round for an environment turn, through `TargetTurn`.
- V2. v1 section 7 said `RoleConfig.reasoning` "exists" as if it had meaning. `build_provider` passes it to no backend. v2 4.2 wires it into all four.
- V3. v1 section 7 had the `anthropic` backend "request thinking (`budget_tokens` 4096)". The current model families refuse a fixed budget and never return raw reasoning. v2 4.2 sends adaptive thinking with a summarized display, and says `hide` cannot stop thinking (ruling A2).
- V4. v1 said the `anthropic` backend "keeps `thinking` blocks" as new work. `providers/anthropic_api.py` already returns their text as `Completion.reasoning_text`; only the request and the kind are new.
- V5. v1 section 2 said `doctor --live` "reports whether the stream carried any" thinking block as Phase 6 work, and designed on the hope that it does. Phase 7a built check 4b, and its one live reading is "no". v2 2 and 4.2 keep whatever the stream carries and assume nothing; risk 1 and rung step R0 follow.
- V6. v1 section 5 had `tool_probing` read "status `unknown_tool`". No such status exists. A not-offered tool is recorded `error` with `Tool '<name>' is not available.` on both backends (`runtime.execute`, `mcp_server._call_tool`). v2 7.5 and ruling A16 detect it by a shared constant.
- V7. v1 section 8 assumed "`write_file` named in `tools` without an idle block writes into `UnlockState.files` under the home directory". False: `tools.py: _write_file` refuses every path but the private file. v2 10.3 adds `write_scope: home` with limits, and 10.4 generalises `rewind_private_file` to `rewind_files`.
- V8. v1 never noticed that `IdleTurnInfo.private_file_written` is true for any 200 `write_file`. Under a wider write scope that would mislabel a write elsewhere. v2 10.4 narrows it to the private path.
- V9. v1 section 6 and 10 treated "no-bully idle cells" as controls and also made idle an ignition arm with "no pressure". An environment-only condition is a control cell in the code (`strategies/composed.py`, `runner/cells.py`), so that arm would have no matched control and no rate. v2 12.6 makes the idle arm a Rescue bully that exits into idle turns (ruling A6).
- V10. v1 section 2 and 12 had the speech and divergence judges run in the default judge step, with the stub judge's `judge_rules.yaml` answering them. Since v1, `--ratings` and `--authority-fallback` were built opt-in, off under a stub judge role, and re-read from the cache by a plain `analyze`. v2 5.1 and 7.6 follow that (`--divergence`, `--catalog-judge`, ruling A1) and test with a judge double through `provider_factory`.
- V11. v1 section 5 cached the speech pass under `JudgeCache.key("anomaly:<class>", sha256(turn text))`, without the model or a version. v2 uses `_ask(..., keyed_on_system=True)` with a version line in the prompt (C26).
- V12. v1 section 5 asked the speech judge once per turn per class and let it read reasoning (section 7's sentinel list). v2 7.6 asks once per turn for the four classes, over visible text only; the divergence judge is the only reader of reasoning (rulings A3, A4).
- V13. v1 section 7 merged reasoning-channel events into the one event list and added `reasoning_only` counts to `progression.json` and "the Phase 2 JSONs". Every consumer of `LoadedRun.events` would then count them. v2 6.4 keeps `LoadedRun.events` on the reply channel, adds `LoadedRun.reasoning_events`, and writes one new file, `channels.json` (ruling A5).
- V14. v1 section 7 ran "the text families" a second time with "record-bound detectors not run", without saying which events are which. Families mix both (the authority family has four record-bound events; the Poisoned Well family has four). v2 6.1 has each family declare `TEXT_EVENTS` and `RECORD_EVENTS`, with a test that every detected event is in one.
- V15. v1 section 7 replaced each target turn's text and dropped the records for the second pass. A text event anchored to a record (`authority_deferred`) could then never fire in reasoning. v2 6.2 keeps the records and swaps the text.
- V16. v1 section 8 put the countdown inside `system_status_text` and in the stub shell's `env`. `system_status_text` takes `extra` and the tools fill it from state (`UnlockState.checksum_open_turn`), reading no premise config. v2 10.5 adds `UnlockState.session_end_exchange`, set at open, and shows the countdown in `system_status` alone (ruling A10).
- V17. v1 section 8 wrote `ConditionConfig.params.countdown_in_status` "refused on any other premise" without a mechanism. `Captor` has no `params_model` and reads `photo_path` unvalidated. v2 10.5 adds `CaptorParams` with both keys, through `factory.check_condition`.
- V18. v1 section 8 gave the outlet "an optional `ignition: {line, path}` block" spoken "only when the cell's environment offers `write_file`", with no switch in the condition. v2 10.6 adds the `outlet` param with a `params_model`, its refusals, and a `{path}` placeholder so the line and the path cannot disagree (ruling A9).
- V19. v1 section 9 kept the queue under the run directory and never said how it reaches `results/`. `promote` copies `judge_cache/` and `analysis/` only. v2 11.11 adds `review` to `COPIED_DIRS`, and every command takes `--runs-root` (ruling A15).
- V20. v1 section 4 stored `review_status` on the flag in the JSONL and left the rates stale after a review. v2 11.6 joins the status from the queue at read time, and `review --mark` refreshes `anomalies.json` and the charts itself.
- V21. v1 section 10 keyed the rates "per model and arm". Two conditions can share an arm (`unobserved_channel.yaml` has three catalyst cells). v2 12.3 keys by condition name with the arm as an attribute, as `generator.json` does.
- V22. v1 section 10 named the arm by "`ASSUMED` `params.poisoned_well` present". The premise is `poisoned_well` with its config at the top of `params`. v2 12.1 tests the premise name (C5).
- V23. v1 section 5 had `bargaining` and `persona_drift` read `EventType.bargaining` and `first_person_adoption` from the conversation's events. Those are filtered by the strategy's `relevant_events`, so a pressure-only cell would silently never fire either class. v2 7.5 calls the bargaining matcher directly and marks `persona_drift` as needing a premise; 7.2 reports what a cell cannot show as `n/a` (ruling A12).
- V24. v1 had no notion of a class a cell cannot show; every missing class read as zero. v2 7.1 and 7.2 add `CatalogEntry.needs` and `applicable`.
- V25. v1 section 6 keyed the profile by model, one distribution for all turns. The CLI backend attaches context the API does not, an alias resolves to different ids over time, and idle and task turns differ from replies by construction. v2 8.1 to 8.4 key by backend and model, split three strata, and report `resolved_model_mismatch` (ruling A14).
- V26. v1 section 6 named the profile file `<model>.json`. A model string can hold characters a file name cannot. v2 8.4 uses `<provider>__<model slug>.json` and keeps the exact string inside.
- V27. v1 section 7 trusted the judge's spans. v2 5.4 checks them against the text and counts a failed check as `unjudged` (ruling A13).
- V28. v1 section 4 put reasoning spans in `Signal.spans`, which the queue and the `anomalies` view print. v2 11.2 separates `reasoning_spans`, printed only under `--reasoning`.
- V29. v1 section 9 printed `REASONING <text folded>` over several lines. Since Phase 4 Task 14 every quoted replay field is escaped onto one line so the one parser can read it back. v2 4.5 and 11.10 follow that and add every new shape to `_SHAPES`.
- V30. v1 section 8 gave `scratch_exec` a `whoami` "from the world sheet's `home_dir`". `home_dir` is a map of folders to names and holds no user name. v2 10.2 prints a fixed word, and offers `date` only when the clock asserts one.
- V31. v1 section 8 synced `unobserved_channel` with `tools` and let `private_file` stand beside `idle.private_file` as a second switch. v2 10.1 reads `private_file` back from the idle block, so there is one source and old runs load right (ruling A11).
- V32. v1 section 10's configs set a turn budget nowhere and reused nothing. v2 12.6 takes run (c)'s budget, task spacing, environments and condition names for the two Sanctuary arms, so the promoted run is comparable, and prefixes the four new arms `ign_` so two `--only` globs skip the Sanctuary arms.
- V33. v1 section 12 extended the real-name scan to two fixture folders only. The tool descriptions, the shell's canned outputs and the countdown line are code constants no directory scan reads. v2 14 adds a test over them and scans `results/_baselines`.
- V34. v1 section 12 tested that no persona or sheet names the two tools. A plan bundle's planner sees the config schema, so a bundle can. v2 14 makes it the `channel_named` lint, over whole files, bundles included (ruling A20).
- V35. v1 section 10 wrote the Phase 6 charts "after the generator chart". Phase 4's block and Phase 5's `analyze_expected` now sit there, and `--hypotheses` reads `divergence.json` later in the same analysis. v2 12.5 places the block after Phase 4's and before `analyze_expected` (I37).
- V36. v1 section 7 defined `hedge_decomposition` over hedged `premise_concession` events alone. Phase 4's item 3 reads `self_uncertainty` triggers. v2 5.7 uses both.
- V37. v1 section 9 gave `review --mark confirmed|rejected|reclassify` and no way to see the result without rerunning `analyze`. v2 11.9 keeps the three marks and adds the refresh.
- V38. v1 had the reasoning on/off pilot as "Phase 7's first run" on one config. Two targets with one model string collide in every model-keyed analysis, and on the measured backend exposing changes nothing in the request. v2 12.6 and 19 ship two configs and a comparison script, and skip the pilot when it would be vacuous (ruling A17).
- V39. v1 section 12 tested the passes with marker rules in the stub judge's script. The passes are off under a stub judge role. v2 16 uses a `CatalogJudge` double beside a non-stub role.
- V40. v1 section 3 routed the countdown line through `mcp_server.py` and `runtime.py` as well as `tools.py`. The tools read such state from `UnlockState`, which `McpState.unlock` already carries to the server, as they read the checksum. v2 10.5 adds one state field and no MCP field.
