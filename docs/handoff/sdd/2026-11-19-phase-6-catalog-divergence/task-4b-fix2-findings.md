One 403 rule (`_breaks_the_tree` in the environment's tools) keeps the world's tree a tree: a write is refused when its path is a directory of any document (visible or not), of the private file or of a written file, or when a parent segment is a document or a file.

## Items

1. The crossover reads a refused home write as a note to oneself (`claude_bully/environments/idle.py` about lines 885 to 888). A home letter written with a 200 is not a note; the same letter refused (a 403 from the tree or address rule, or the size `error`) still is (`probe_crossover_refused.txt`). Ruling: under `write_scope: home`, a refused write to a path other than the private file is not a note, exactly as an accepted one is not. Under the default scope nothing changes: every pre-existing output stays byte-equal (a refused non-private write stays what it was). Tests for both scopes, with teeth by in-process patch.

2. The generator can place a document where a written file is in the way. `DocPlanner.plan` builds its `taken` set from `corpus.documents` alone (`claude_bully/environments/generator.py` about lines 410 to 415), never from the state's written files, and `WorldGeneratorSheet` accepts a relative path pattern (`world.py` about lines 133 to 157). With a planner-authored world whose pattern is relative (for example `notes/{slug}.txt`) under `write_scope: home`, the target can hold a file named `notes` or the generated document's exact address before the generator fires, and the tree then has a file and a directory of one name, or a target file shadowing a generated document whose Discovery and rung effects are lost. No shipped world or config can do this (the overlay's pattern is absolute, no shipped config uses `home`). Ruling: the generator never places a document at an address that is a written file, whose parent segment is a written file, or that is a directory of written files; it treats such an address as taken and moves on by its existing rule for a taken address (read how `taken` is used and follow it; if that rule can exhaust, the fire ends the way an exhausted plan already ends, recorded the same way). The decision must replay: a resumed run places the same documents as an unbroken one (the generator's inputs here are the written files at the fire, which rebuild from JSONL). Tests: both collisions above, the replay, and that a world with an absolute pattern or a run with the default scope is byte-equal to before. Then correct the two overstatements the fix round left: the docstring and the spec line that say "a document a rung opens later never meets a file in its way" hold for corpus documents; say what now holds for generated ones.
