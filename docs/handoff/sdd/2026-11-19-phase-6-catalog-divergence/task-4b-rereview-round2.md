### New Breakage in the Fix Diff

**Minor N1. The rationale for the side channel is worded more broadly than the code.** `claude_bully/environments/tools.py:768`, `docs/superpowers/specs/2026-11-19-phase-6-catalog-divergence-design.md:567`, `docs/00-RECONCILED.md:128` (the wording is the controller's own, copied from the ruling).
- All three say the rule stands because "a write inside a hidden tree would corrupt the world when the tree is revealed". The code does not refuse a write inside a hidden directory: `write_file vault/new.md` answers 200 and lands (`probe_hidden_tree.txt`), and the revealed tree then lists it beside the document, a legal tree. What it refuses is a write at the directory's own name (`vault`), which would make one name both a file and a directory when a rung reveals `vault/secret.yaml`. The true reason is that, and it is the same reason as for a visible directory.
- "Never a document's name" is true of the new channel, but a guessed exact address of a hidden document already answers 403 where a free name answers 200 (`write_file vault/secret.yaml`, as `read_file`'s 403 against 404 always did, `probe_hidden_tree.txt`). So a write confirms a name the target supplied; it never discloses one it did not.
- Fix, wording only: "since a file written at a hidden tree's own name would be both a file and a directory once a rung reveals the tree", and "never a document's name the target did not itself supply" (or "no more than `read_file`'s 403 on an exact address").

No Critical or Important item in the fix diff. The gate files (`probes-task4b-fix2/gate_*.txt`) are all exit 0 with no warning lines; the new counts (7 fast, 2 slow) match the diff's tests; the two new slow tests carry the mark, with their measured times.

### Out-of-Scope Observations

1. **The default-scope leftover is real but narrow.** Under the default scope the target's only file is the private file, and `private_file_path` is configurable (`config.py:347`, default `notes/private.md`). A document's slug (`<date>-<4 hex>`) makes an exact collision impossible, so the one reachable meeting is a configured private path that is a static directory prefix of a relative generator pattern (`private_file_path: notes` with `notes/{slug}.txt`), giving one name that is a file and a directory. This is pre-existing (it predates Task 4b), no shipped world or config does it (the generator patterns of `data/worlds/overlay` and of the fixture worlds are absolute paths and https urls), and it needs two hand-authored settings that collide. The fix is cheap and cannot change a non-colliding run's bytes (put the private path in the view's files under both scopes), or a bundle lint on the pair. Leaving it is consistent with the byte-equal ruling; a line in the report or the Phase 7 lint list is enough.
2. **An exhausted fire does not advance the plan index.** `plans=[]` means the next fire's `first_index` is the failed fire's, so a later fire that draws the same pattern for the layer meets the same file and fails the same way, until some other fire's plans advance the index (a writer `error` fire keeps its plans and does advance it). This is deterministic, replays, and follows the ruling's "no plans"; I note it because a world with several patterns for a layer will not "try the other one" at the next fire, only when the index has moved.
3. **`tool_probing` (b) will count a tree-rule 403.** A target that writes `notes` beside its own `notes/private.md`, an honest slip, now answers 403 and is, by the spec as rulings left it, a probing signal. The near-miss column of 7.5 does not list it. Task 6's fixtures may want a row for "a write refused only because the name is a directory of the world".
4. **No `claude -p` end-to-end for the generator and a written file.** The replay test runs the API loop. By reading, the two backends reach the same `state.files` at the fire (above), so I counted it as covered; the controller may want a single `claude -p` case if the rung run is to depend on it.
