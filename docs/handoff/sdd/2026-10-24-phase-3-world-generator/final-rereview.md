Nothing else grew. The ceiling was the breaker brief's guard against the module growing by open-ended rules (`task-3-breaker-fix.md:40`); these additions are the opposite kind (closed lists and an offset fix), and the N7 ruling already parks the module's future on the Phase 7 LLM-lint decision. My call: accept the overrun and record 1185 as the new figure in the ledger beside N7, rather than trim; a trim now would only move lines out of a module Phase 7 may replace.

**The third copy of the `PermissionError` retry loop.** The three copies (`runtime.py:437-449` `_write_atomic`, `mcp_server.py:143-153` `_replace`, `judge.py:123-131`) are the same shape today (20 x 50 ms, unlink the temp on exhaustion), so the drift risk is prospective, not present. A shared helper in a stdlib-only leaf module (say `claude_bully/atomic.py` with `replace_with_retry(tmp, path)`; `judge.py` already imports only `records`, `providers.base` and `enums`, so a leaf module creates no cycle) is the right fix, and it is a fifteen-line change with the tests for all three paths already in place. Not worth a commit of its own now: park it, bundled with Task 4 M7 (the cache key must change before Phase 7 and that change touches `judge.py` anyway), with the leaf-module shape named in the ledger so the fourth copy never happens.
